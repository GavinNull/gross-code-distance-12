### 1.2 语义检查（覆盖全部已认证实例，包括 u11 与 gross）

u11 用的 L 来自评估器（E-032 `common.HLk`），我用 release 的 L，所以文件不会逐字节相同。为此另写了 `semcheck.py`，只看约束的含义，对 E-031 的 .opb 逐条判定：

- 每条约束必须是五种形状之一：检查行 Σx − Σ2^{k+1}a = 0；逻辑行 Σx + q − Σ2^{k+1}b = 0；权重 Σ −x ≥ −W，且覆盖**全部** N 列；Σ_全部 q ≥ 1；子句 Σ¬x ≥ 1。其他形状一律报错。
- 辅助位：每个 a、b 变量只出现在一条约束里；第 k 位系数恰为 −2^{k+1}，k 连续；2(2^K − 1) ≥ 行长（逻辑行再加 1）。所以每条“= 0”等价于“该行 x 和为偶”（检查行），或“q = 该行 x 和的奇偶”（逻辑行），并且 0/1 下的辅助位由 x 唯一确定。每个 q 恰好出现在自己的行和 Σq 里。
- 检查行的列集合（多重集）= 我从电路自己算出的 Hc 的行。
- 逻辑行：在 GF(2) 上 span(对方的行) + rowspace(Hc) = span(我的 L 行) + rowspace(Hc)，商空间维数 = k（[[90]] 8，gross 12）。这正好是“在 ker Hc 上，某条对方逻辑行为奇 ⇔ L x ≠ 0”的充要条件。
- 阻断子句的集合 = 给定列表（逐个作为列集合比较），列表中每一项都在我的编码下是逻辑（Hc 和为 0、L 和非零），且两两不同。
- 没有 H 部分为零的列（见 1.4）。
- 对每个平移：检查行、逻辑行、阻断集合都映成自身。

### 1.3 L 平移行加 Σq ≥ 1 为什么正确且完整

- 完整（不会多排除）：原始 L 行都在其中（L 行在列上不为零向量时）；任一满足 H x = 0、L x ≠ 0 的 x 至少使一条原始行为奇，取对应 q = 1，Σq ≥ 1 满足。
- 正确（不会多放进）：每条平移行在列上 = 若干原始 L 行 + 若干 Hc 行（上面的秩检查），所以在 ker Hc 上它为奇 ⇒ 某条原始 L 行为奇。
- q 本身不受约束（除 Σq ≥ 1），由逻辑行等式唯一确定为奇偶，不能被“假设”为 1。

### 1.4 阻断子句：阻断的是超集，但这里与阻断支撑本身相同

子句 Σ_{j∈B} ¬x_j ≥ 1 排除的是所有包含 B 的 x，不只是 B。设 x ⊋ B、|x| ≤ W、H x = 0。B 是逻辑，所以 H(x \ B) = 0 且 x \ B 非空，|x \ B| ≤ W − |B|。实际实例中 W − min|B| ≤ 1，而没有 H 部分为零的列（semcheck：零个），所以不存在这样的 x。于是“UNSAT ⇒ 权重 ≤ W 的扩展逻辑恰是列表中的这些”成立，没有多排除。

### 1.5 独立枚举（可满足方向与不可满足方向一起比）

`mitm.c` + `enum.py`：在自己的列上做中间相遇枚举（x 含某个轨道代表 r，x \ {r} 按编号拆成前后两半，后一半的综合征表排序后二分查找），对全部轨道代表跑，再用群闭包。

- **[[90]] 两基底**：权重 1–7 的扩展逻辑个数为 0；权重 8 恰 585 个、权重 9 恰 16830 个，**与 release 列表逐个相同**（`results/E-031-audit/enum/enum.jsonl`）。
- 每一个找到的逻辑都满足 E-031 对应 .opb 的全部非子句约束（q 与二进制位由我计算），并且恰好被阻断子句挡住：W7 实例 0 个逻辑；W8 实例 585 个全部被挡；W9 实例 17415 个全部被挡。所以三个实例在我的枚举下都是 UNSAT，与 VeriPB 的结论一致；反过来对方公式也没有把任何真解排除。

### 1.6 对称步骤（`red`）

证明结构（我对重新生成的 [[90]] Z W7 证明做了统计）：`f 290` 载入全部 290 条约束；`strengthening_to_core on`；220 条 `red`（= 225 列 − 5 个轨道）全部在第 4–223 行，**早于任何推导与删除**；之后只有 `pol`、`rup`、`del`；`del` 删除的编号都 ≥ 511（只删推导出的子节点证书，从不删原始约束或对称子句）；最后 `output NONE`、`conclusion UNSAT : <id>`。没有任何未经检查的规则（无 assumption 一类的步骤）。

可靠性论证：`red` 规则由 VeriPB 自己检查 F ∧ ¬C ⊨ (F ∧ C)|σ 的每个目标；σ 是一个平移对 x、q、a、b 的整体换名，公式在 σ 下逐字不变（1.2 与 build.py 的 `check_automorphisms` 都核对过），所以目标就是之前加入的对称子句的像，而这些像在 ¬C 下要么含已为假的较早轨道变量取反、要么含 x_g。所有 `red` 都在删除之前，所以之后的删除不会让某个 `red` 在被削弱的核心上被检查。之后的 `rup`/`pol` 都是蕴含推导，与删除无关地可靠。

篡改测试证明 VeriPB 真的在检查见证（第 2.3 节）：把第一条 `red` 的见证改成非自同构（x1 → x5）、或只保留 x 部分（q、a、b 不换名）、或把子句改成单元 ¬x2，**全部在第 4 行被拒**（“Could not prove proof goal …”）。

一个值得记下的观察：**最后一个轨道的对称子句其实可以直接用 `rup` 得到**（把最后一条 `red` 改成同一子句的 `rup`，VeriPB 接受）。所以对最后那条 `red` 做的篡改（只保留 x 见证、换成重言式）也被接受——这不是漏检，被删掉的步骤本来就是多余的，剩下的证明仍然正确。

### 1.7 “逐字不变”

build.py 的 `check_automorphisms` 对每个群元把整个约束多重集换名后比较，`write` 在写文件前调用它。我的 semcheck 独立核对了：每个平移把检查行集合、逻辑行集合、阻断集合各自映成自身；由于每行的辅助位只属于该行，行之间的双射就给出 a、b 的换名，q 跟着逻辑行走。因此公式在群下逐字不变（变量换名意义下），这正是 `red` 的见证所需要的。**CONFIRMED。**

## 6. 发现的问题（交给 lead）

1. **论文措辞过强**（第 5 节）：“every computational input” 要换成 “every infeasibility claim”，并写明编码由我们的代码生成、约化是论证。日志续篇结论里“c16 定理的全部计算输入都有可检查的证书”同样要改；它自己的括号里已经承认任意 R 的前提是计算核对，与这句话矛盾。
2. **c11 缺 R = 20–25**（约 3.5 CPU h，按日志），c13 没做（约 2.5 CPU h）。c11 已有的 R ≤ 19 中 292 批只经 drat-trim。
3. **BB72 种植测试是退化的**：权重 5 列表只有 1 个轨道（36 个），`--drop-block 0` 去掉了全部阻断，`bb72_Z_W5_drop0.opb` 与不加阻断的 `bb72_Z_W5.opb` sha256 相同。“找到的正是被去掉的那个”因此不检验阻断。[[90]]（13 个轨道）和 gross 的种植测试不退化，所以结论不受影响，只是日志中 BB72 那一行的说法应改。
4. **VeriPB 的成功判据**：`conclusion NONE` 时 VeriPB 也打印 `Verification succeeded.` 并返回 0（输出 `s VERIFIED NO CONCLUSION`）。certify.py 要求 `s VERIFIED UNSATISFIABLE`，所以没有问题；任何复现脚本（包括发布包里的 run_quick）都必须用同样的判据。
5. 小事：最后一个轨道的对称子句可直接 RUP（D1），对称步骤只在前 4 个轨道上起作用。不影响任何结论。
