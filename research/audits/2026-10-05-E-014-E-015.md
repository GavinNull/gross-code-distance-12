### A2. Symmetry group

- All 72 translations are code automorphisms (BB coordinates); exactly **24** preserve every check's CNOT order

  coordinates ((di, dj) with di + dj = 0 mod 3, i.e. colour preserving).
- **Logical classes preserved** (the point raised in the brief): for each of the 24 translations T, I solved
  L o T = M L + N H over GF(2) for the relevant pair (L, H) of each side and checked rank(M) = k = 12. So

  reduction needs. Holds on both sides, both constructions.
- Action on merged columns well defined (assertion over all raw supports) and a permutation; 15 orbits of size 24
  per side; **the orbit partition equals the lead's** (compared through the column bijection of A1), and every
  lead rep lies in its own orbit.

### A4. Split completeness (`a3_validate.py c`)

## B. E-015

### B7. `ibm_lift.py`: IBM [[72,12,6]] depth-8 circuit, d_circ = 6 (`b_ibm.py`, `b7_periodic.py`)

**The argument, written out.** Fix a memory basis, say Z (X basis is symmetric). The evaluator's detectors are
Z-check comparisons of consecutive cycles plus final detectors (data readout parity vs last cycle); I checked this
on the circuit (`b7_periodic.py`, all 252 detectors of R=6, both bases). Hence, for a set F of circuit faults,
the product of all detectors of check i equals row i of H_Z applied to the X part of the data Pauli frame at the
end, x_F = sum over f in F of x_f, where x_f is the end-of-circuit data X part of fault f alone (Pauli frames are
linear). So F undetected and logical => H_Z x_F = 0 and L_Z x_F != 0.
Table I (Prop. 3's key step): every single fault has x_f = 0 or x_f = the support of exactly one extended-code
column (data qubit or residual suffix). Then the [H; L] vectors of the x_f are each 0 or a column c_f.
Cancel equal pairs: the set T of columns occurring an odd number of times has sum [0; nonzero], i.e. T is an
extended-code logical, |T| <= |F|. With d_ext = 5: every undetected logical F has |F| >= 5 (Prop. 3), and if
|F| = 5 then |T| = 5 = |F|, which forces **all five images nonzero and pairwise distinct** (a zero image or two
faults on the same column would give |T| <= 4 resp. |T| <= 3, and an extended logical of weight <= 4 does not
exist). So the images form a weight-5 extended logical S, one fault per column.
Faults are counted as DEM error mechanisms: replace each DEM term by one of its circuit locations (same symptom).
Hence: d_circ = 5 iff for some weight-5 ext logical S one can pick 5 distinct DEM terms, term j having a location
whose image is column S_j, with detector XOR = 0 and observable XOR != 0. This is exactly what ibm_lift.py decides.
The two cases asked about ("two faults on one column", "a fault with image 0") are excluded by the parity/size
argument above; they would only matter at weight >= d_ext + 2.

**Independent recomputation** (nothing from ibm_lift.py / e015 used except the schedule source
`default_schedule`; the circuit is the evaluator's `build_circuits` + `add_noise('sd6')`):
- Own BB72 matrices = evaluator task; per-check orders read off the stim circuit itself (identical in every cycle).
- Own extended codes, **all** logicals by brute-force meet in the middle: weights 1-4: none; weight 5: 36 (X-type,
  Z basis) and 252 (Z-type, X basis) -- same numbers as the lead's DFS enumeration.
- Own fault enumeration (every Pauli component of every noise instruction) and own bit-parallel frame simulator.
  For every R = 1..10 and both bases: the set of my nonempty fault signatures **equals stim's DEM error set**, and
  for every DEM term **the number of circuit locations equals the number listed by
  `explain_detector_error_model_errors(reduce_to_one_representative_error=False)`** (e.g. R=8: 42,192 = 42,192).
  So that stim call does list all locations here, and ibm_lift's grouping (every location of every term) is complete.
- Table I: 0 exceptions, all 180 columns realised, every R, both bases.
- Exact search (my own MITM over DEM terms, one per column, distinct): **0 undetected logicals of weight 5 for
  R = 1..10, both bases** (ibm_lift: R = 1..8). Positive control with w = 6 (no distinctness theorem needed, just
  the restricted search): R=1,2 find 222/360 (Z) and 324/564 (X) weight-6 undetected logicals.
- Upper bound 6: any weight-6 data logical injected as reset faults; true for every R.

**Arbitrary R.** The lead's informal "a minimal logical cannot span an empty round" can be made rigorous here:
1. Separation (checked, `b7_periodic.py`): in the unrolled circuit, the CNOT ticks of cycle k of all 72 checks lie
   in [8k+1, 8k+7] and those of cycle k+1 start at 8k+9. Assign each fault to a round: ancilla faults to the cycle the
   ancilla is in; data faults at tick t to the round whose CNOT window contains t or follows the gap tick before it.
2. Split lemma: if F is an undetected logical and round r (strictly between F's first and last round) contains no
   fault of F, put F_< = faults in rounds < r, F_> = the rest. Under F_< alone the data frame is constant e from the
   end of round r-1's CNOTs on, so every cycle >= r measures H e and every detector comparing cycles >= r (and the
   final ones) is 0; detectors comparing cycles <= r involve no measurement F_> can reach, so under F they equal
   F_<'s, hence 0. So F_< and F_> = F \ F_< are both undetected, and obs(F) = obs(F_<) + obs(F_>): one of them is an
   undetected logical with fewer than |F| faults. For |F| = 5 = d_ext this contradicts Prop. 3. So a weight-5
   undetected logical occupies at most 5 consecutive rounds.
3. Periodicity (checked): for R = 2..11 the noisy R+1 circuit is the R circuit with one 8-layer block inserted at a
   fixed position after the first round. So a weight-5 logical in rounds [a, a+4] of a long circuit can be
   translated to a circuit with at most 7 rounds (one clean round on each side that does not touch a boundary; the
   detector values only depend on these rounds), and R = 1..7 are covered by the exact runs.
Hence **d_circ = 6 for every R >= 1**, both bases. Caveat: step 3's translation is argued from the verified block
structure, not by an additional computation; I am confident in it, but it is a written argument.

**Verdict B7: the R <= 8 proof is correct (CONFIRMED, reproduced to R = 10); the arbitrary-R extension holds with
the argument above (CONFIRMED as a proof sketch with machine-checked hypotheses).**

   witness *weight*, not the witness. Every negative statement backed by "verified heuristic witnesses" (gross,
   [[120]], [[124]], [[140]], WM[[180]]) is therefore not checkable from the artefacts. I re-derived gross and stored
   the witnesses (`b8_gross_X_*.json`); the others remain unverifiable as recorded. Fix: write the column set (or
   supports) of each witness into the jsonl.
2. **(E-015, medium: reproducibility)** The cp126 / [[120]] / [[124]] positive proofs were run with "session-local short
   scripts" that are not in the repo (journal, last code block). The stored spec in `assembled_*.json` was enough for
   me to redo them, but the journal's "one command reproduces it" rule is not met. Suggest adding my
   `b6_theorems.py` (or an equivalent) to the experiment.
3. **(E-015, low: wording)** "IBM 原电路 d_circ = 6 在 R = 1..8 轮都已证明 / 任意 R 未证": with the argument in B7 the
   statement holds for every R; if the journal is to claim that, it must carry the argument and its three checked
   hypotheses (not the informal one-liner). Also `ibm_lift.py`'s module docstring still describes a CP-SAT decision
   while the code does an exact meet in the middle; and its right half does not reject repeated DEM terms (can only
   create false positives; irrelevant for the 0-hit result).
4. **(E-014 / E-015, low: tooling)** `dfs128.c` (both copies) does not check `fopen`/`fscanf` failure: a missing
   instance file segfaults and writes no SUMMARY line. Any pipeline must count SUMMARY lines (the lead's E-014 run
   has 48/48; mine are counted in this report).
5. **(E-014, process)** The lead's `pkill -f` (self-reported in the journal) violates the PID-only rule; no evidence it
   affected other runs.
6. **(scope)** Novelty of "d_circ(Fig. 12) = 11 proved" and of the E-015 theorems was not checked in this audit;
   a lit-scout pass is still needed before any public claim (CLAUDE.md rule 6).
