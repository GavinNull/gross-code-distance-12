**关于最强的一条声明“BB90 非交错电路不可能达到 10”，我能确认的准确表述是：**
对 [[90,8,10]]（IBM Table 3 多项式），任何满足下面四条的电路，电路级距离都 ≤ 9：
1. 每个校验一个专用辅助比特，用 6 个依次执行的 CNOT 测量；
2. 可以在时间上分段，也就是插入无错 idle 后能切成只含 X 校验 CNOT 和只含 Z 校验 CNOT 的交替段；
3. 噪声是 SD6 / 标准电路噪声，CNOT 之后辅助比特上的单比特 Pauli 是单个故障；
4. 深度、轮数、调度是否均匀、每轮顺序是否相同都不限。

**不覆盖的情况：**交错电路；IBM 那种“两两不交错但不能全局分段”的流水电路；flag 或多辅助比特电路。H-004 的“10 不可能”只能写成“在可分段的非交错电路类中不可能”。

## 1. 理论核对

### 1.1 扩展码 E 的构造（我的理解，与 E-005 一致）
- **残余错误**（Sec. IV.A，Def. 1 前的公式）：一个校验按电路顺序作用在 i_1, …, i_w 上，残余集合是全部后缀 {i_l, …, i_w}，l = 2..w。
  - Z 校验：Z 辅助比特在第 l−1 个 CNOT 之后出现 Z 错，会沿后续 CNOT（数据是控制）传到 i_l..i_w。
  - X 校验：X 辅助比特出现 X 错，沿后续 CNOT（辅助是控制）传给目标。
- **扩展码**（Def. 2）：Z 型残余追加到 (H_X, L_X) 后面，X 型残余追加到 (H_Z, L_Z) 后面，每列是该残余支撑上各数据列的模 2 和。
- **d_ext**（Def. 3，Eq. 7–8）：d^Z_ext = min|x|，约束 H_X^ext x = 0 且 L_X^ext x ≠ 0；d_ext = min(d^X, d^Z)。
- **列等价**：长度 1 的后缀就是一个数据列。长度 w−1 的后缀和第一个比特的数据列只差该校验本身。该校验对 [H; L] 里另一型的矩阵来说是零列，因为同型稳定子既与对方校验对易，也与对方逻辑对易，所以两列**完全相同**。去掉这两种列不改变任何最小值。
- **单校验的类数**：每个校验只剩 3 个新列：{p1,p2}、{p1,p2,p3}（≡{p4,p5,p6}）、{p5,p6}。反转顺序得到同一组列，所以类数是 720/8 = 90。
  - 实测（`t0_codes.py`）：三个码的 X、Z 校验都恰好是 90 类，每类 8 个顺序，每类 3 个新列，与论文和 E-005 一致。
  - 插曲：我的第一版和 E-005 一样犯了 dtype 错误（uint64 与 uint8 按字节比较），得到 360 类，靠“90”这个检查数抓了出来。

### 1.2 “非交错”的精确定义：需要全局分段
- **论文 Sec. II.A 的文字定义**：“either all X-type CNOTs precede all overlapping Z-type CNOTs, or all Z-type CNOTs precede all overlapping X-type CNOTs”。这句话可以读成两两条件。
- **Prop. 2 和 Corollary 1 的证明实际用的是**：插入无错 idle 后，电路能在时间上切成 X 段和 Z 段。这是全局条件。
- **我的判定（`audext.pairwise_and_partition`）**：把周期调度展开 R 轮，每个校验实例是一个节点；在每个数据比特的时间线上，相邻事件连边，类型改变的边权 1，同类型的边权 0。能分段等价于没有任何强连通分量含权 1 的边（有限轮下用最长路给出相位）。
- **两种条件确实不同**（`t2_partition.json`）：

| 电路 | 两两不交错 | 可分段 |
|---|---|---|
| gross Fig. 12 | 是 | 是 |
| IBM 深度 8（gross、BB108、BB90，R = 2, 3, 4, 8） | 是 | 否（最大 SCC 同时含全部 X 和 Z 校验） |

- **分段这一前提确实承重**：
  - IBM BB90 的全 E d_ext：我独立精确计算得到 d^Z_ext = 6、d^X_ext = 7，与 E-005 的自检一致。评估器上界是 8（§4）。如果 Corollary 1 的等式适用于 IBM，评估器理应能找到 6。
  - 更直接的证据：IBM BB90 第 0 号 X 校验的单校验扩展码有一个权重 8 的最优见证。在 IBM 电路里，对“每个数据错误放在任意层之后 + 钩子放在任意一轮”做 CP-SAT 穷举，结果是 **INFEASIBLE**（`single_realize_bb90_X0.json`）。同样的流程在可分段的 LRC 电路里可以把权重 9 的单校验见证实现成 0 个 detector 触发的逻辑错误（日志见 §4）。
  - 所以单校验上界**不能**推广到只满足两两条件的电路。E-005 第 5 节第 2 条说“单校验上界对任何非交错电路成立，不依赖这个检查”，只有把“非交错”定义为可分段时才对。在两两定义下这句话没有证明，而且上面的 IBM 实验说明论证本身确实会断。这不影响 E-005 的结果，但影响结论的措辞。
- **E-005 的判定与我的判定一致**：E-005 用的是“周期势 a_x − b_z = 阈值、全局一致”，我用的是有限展开 SCC。
  - 理论上，势一致可以推出可分段（构造 φ = 2(s − a_x) + 1、ψ = 2(r − b_z) 即可）。
  - 抽样对比（`t13_partition_compare.json`，BB90 深度 8 均匀空间）：E-005 判为非交错的 150 个，在我的判定下 150/150 可分段；不在其可行表里、但无数据冲突的 259 个（其中 8 个两两一致），0/259 可分段。

### 1.3 “对所有非交错电路取上界”的推理（Prop. 4 → E-005 C1）
对任意可分段电路 C，固定第 0 号 X 校验，取它出现的某一轮实例，以及包含它的 X 段：
- 在该段内，数据比特上的 X 错可以放在相邻的段边界之间。SD6 的每个 CNOT 之后都有含单比特分量的 DEPOLARIZE2，所以总有一个故障位置。
- 第 0 号校验的辅助比特钩子只会把错误传到后缀。
- 每个 Z 校验实例对这些错误“要么全看见，要么全看不见”。
- 所以扩展码 (H_Z, L_Z) + R_0 里任意权重 w 的逻辑，都对应一组 w 个不触发 detector、翻转逻辑的电路故障，即 d_circ ≤ d^X_ext(R_0)。

由此得到：
- R_0 由该校验的 CNOT 顺序决定，属于 90 类之一，所以 d_circ ≤ max_i d^X_ext(R_i)。
- **只需要上界见证**（每类一个已验证的低权逻辑），不需要求解器的不可行证明。
- 论证不需要平移对称（固定任何一个校验都行），对每轮顺序不同、非均匀、任意深度、任意轮数（≥ 1，含末轮）的电路都成立。
- **X 侧单独就足够**：如果 max_i d^X(R_i) = 9，那么 d_circ ≤ 9。
- E-005 说“穷举了 90 类 × X/Z”：类划分正确，X 侧 90 类全部覆盖。

我还在可分段的 LRC 电路上直接实现了一个单校验见证（只在第 0 号校验放钩子），见 §4。

### 1.4 Theorem 1 其余部分
- Prop. 3（d_circ ≥ d_ext(E)）只用于下界，E-005 的核心声明不依赖它。
- 交叉验证里所有评估器上界都 ≥ d_ext，没有反例。

说明：
- 对应关系是：Z 基 memory 失败 ↔ X 型故障 ↔ d^X_ext。
- 单校验机制的直接检查：LRC 电路第 0 号 X 校验的单校验扩展码最优值是 9（只有 1 个钩子 + 8 个数据错），在电路里实现后 0 个 detector 触发、3 个 observable 翻转。
- 局限：两个 BB90 可分段电路的值都是 6，属于低端，没能检验评估器在 8–9 这种高值上的表现。gross 的 11 覆盖了高值，但那里只有上界一侧。

## 5. 发现的问题

1. **（措辞，重要）**E-005 一句话结论和 §3.1 的“任何非交错单辅助比特电路（任意深度）d_circ ≤ 9”必须加限定“可分段（全局轮次一致）”。§5.2 中“单校验上界……不依赖这个检查”应删除或改写：证明依赖分段；IBM 类两两不交错的流水电路不在范围内，而且单校验见证在 IBM 电路里确实实现不了（§1.2）。H-004 的“S1 证明非交错上界 < 10”只排除了可分段电路，交错和流水电路仍然开放，这与 H-004 写的“必要时扩展到交错 / 流水”一致。
2. **（验证缺口，E-005 自己已承认）**gross Fig. 12 的 d_ext 精确值和 gross 单校验 90 类都没有完整复现。我补上了“≤ 11 + 电路实现 + 评估器 11”，但“= 11”仍然 INCONCLUSIVE。这不影响 C1–C5，因为它们都是有显式见证的上界。
3. **（可加强）**C4 可以加强为“任何所有 X 校验同一项顺序的可分段电路 ≤ 8”，不限深度 8。这进一步说明 BB90 上只有非均匀电路才可能到 9。
4. **（小问题）**`search/noninterleaved/ext.py` 模块文档写的是“Exact solver: OR-tools CP-SAT”，实际结果都用 HiGHS（`min_weight_milp` / `feasible_milp`）。另外，单线程 CP-SAT 在这类问题上基本无效：我测得 300 s 下界仍是 0，HiGHS 9 s 就求到最优。建议改文档。
5. **（复现性）**E-005 的代码没有提交（untracked）。审计依据的是 2026-10-03 磁盘上的版本。
6. **（审计自身）**`single_realize_bb90_X0.json` 先存 LRC 结果，后被 IBM 结果覆盖（文件名冲突）。LRC 的数值见本报告 §4 和 §1.2 的转述，没有单独存档。
