## Stage 1: independent construction and legality

Own code: `aud13.py` (construction, own stim memory generator with SD6 noise, own non-interleaving / SCC partition
test) and `s2_legal.py`. Nothing imported from `search/noninterleaved/` except, after the independent build, to compare.

**Finding F1 (documentation error, the circuit is fine).** The rule as written in the audit brief, and as worded in the
E-013 journal ("Z side: even rows first block=(2,1,0), second block=(0,1,2)"), is **not legal** if "first block" is read
as the first block in CNOT order (the B block for Z checks): it gives **54 data-qubit collisions** (Z checks of
opposite row parity hit the same L qubit at t=5 and t=7, because y^3 and x^2 differ by an odd y-shift).
The lead's code (`colour_search.order_terms(kind, pi, sigma)`) takes the tuple as (pi on A, sigma on B), so for Z
checks the first tuple element permutes the **A block, which comes second in time**. The circuit that was actually
evaluated is

| | even rows (b even) | odd rows |
|---|---|---|
| X (CNOT t=1..6) | [0,1,2,5,3,4] | [2,1,0,5,3,4] |
| Z (CNOT t=5,6,7,0,1,2) | **[3,4,5,2,1,0]** | [3,4,5,0,1,2] |

i.e. in the Z checks the B block is (0,1,2) in both parities and the A block is reversed on even rows. This is
consistent with the journal's "one-sentence rule" (reverse the order inside one block by row parity). The journal's
block listing for the Z side should be corrected to say A block (2,1,0) / B block (0,1,2) (or list the term orders).

With the corrected Z_even order:
- Data-qubit collisions: 0; every check: prep, then 6 CNOTs at distinct offsets inside the window, then meas,
  supports exactly match HX / HZ rows (54 + 54 checks, all rows including redundant ones).
- Evaluator `validate_schedule`: no problems. Evaluator code (task bb108-dcirc) has the same HX, HZ as baselines BBCode.
- **Gate-by-gate identical to the lead's schedule** (`assemble.py --x 2 14 --z 12 0` via `from_baseline`):
  all 108 CheckTimings equal, same canonical hash.
- Own memory circuits (own unrolling, independent of evaluator template), Z and X basis, 1-4 rounds: DEM builds with
  `allow_gauge_detectors=False`; noiseless sampling flips no detector and no observable; 8 observables.
- Non-interleaving (own test, 6 unrolled rounds): 17496 overlapping (X instance, Z instance) pairs, **0 mixed**;
  precedence graph SCCs contain **0 type-changing edges** => partitionable (consistent global X/Z phase).

## Stage 3: exact proof attempt (written early because it was fast)

### Theorem used
Strikis, Browne, Beverland, arXiv:2603.05481 v2 (read from the PDF):
- **Prop. 3**: for *any* single-ancilla CNOT-based SEC (interleaved or not), d_circ >= d_ext(E), E = full residual set.
  The proof needs: CSS code; each check has a dedicated ancilla; memory experiment whose last syndrome comes from
  measuring all data qubits; every circuit fault mechanism, propagated to the end, has data support equal to one
  data qubit, one residual (suffix of a check's CNOT order) or nothing (their Table I; a ZZ fault on a data/Z-ancilla
  CNOT equals the next residual). No assumption on the number of rounds. d_circ is defined there as the minimum number
  of error mechanisms that flip no detector and flip an observable, per basis, exactly the evaluator's quantity.
- So the **lower bound does not even need the non-interleaving property** (Corollary 1 is only needed for the
  converse, d'_circ <= d_ext).
- Upper bound: the injection-verified weight-10 witness (stage 2a) gives d_circ <= 10 in both bases.
Hence d_ext(E) >= 10 in both X and Z implies **d_circ = 10** (per basis) for the evaluator's memory circuits for any
number of rounds, under any noise model whose fault mechanisms are single circuit-operation faults (SD6 included).

### Own extended code (`extcode.py`)
Z-type: (HX, LX) + suffixes {i_l..i_6}, l=2..6, of every Z check's CNOT order; X-type analogous with (HZ, LZ) and the
X checks. 108 data + 270 raw residual columns; after dropping zero columns and merging identical (H,L) columns:
**270 columns** each side (108 data of He-weight 3, 108 of weight 6, 54 of weight 9), 54 He rows (row weight 27), 8 L rows.
The column set is identical to that of the lead's `ext.extended_matrices` (checked as a set).

Symmetry: the 27 translations x^a y^b with b even map even rows to even rows, so they map each check's order to the
order of the image check, hence the residual set to itself, and they are code automorphisms. A translation acts on a
column of [He; Le] by a row permutation on He and an invertible linear map on the logical coordinates, so identical
columns map to identical columns and the action descends to merged columns. Checked numerically (assertions in
`extcode.py`: residual set invariant, action on merged columns well defined and a permutation). Result: 10 orbits of
size 27 on each side.

### Exhaustive search (`dfs.c`, own C code)
Question: is there x with He x = 0, Le x != 0, |x| <= W? Completeness argument:
1. If yes, take a minimum-weight such x*. It is syndrome-minimal: if a proper nonempty subset y had He y = 0, then
   either y or x*+y is a lighter logical. So a DFS that stops at syndrome 0 reaches x* if it can grow x* from inside.
2. Let o be the lowest orbit index met by x*. Translating x* (weight, He-kernel and logicality are preserved) we may
   assume x* contains rep(o) and no column of orbits < o. Case o: start from {rep(o)}, forbid orbits < o.
3. Branching: S subset of x*, He S != 0. Pick an odd row r of He S; x* has even parity on r, so x* \ S contains a column
   of r. Branch over available columns c_1..c_k of r; in branch i forbid c_1..c_{i-1} (the branches partition the
   space: branch i = "c_i is the first of r's columns in x*").
4. Prune when depth + ceil(popcount(syndrome)/9) > W (each column flips at most 9 rows) or an odd row has no
   available column. With one column left, look the syndrome up in a hash of column vectors.

**Result: W = 9, both sides, all 10 cases: 0 solutions** (Z: 1.44e9 nodes, 45 s; X: 1.47e9 nodes, 47 s, single
thread). Output `results/E-013-audit/dfs_W9.txt`. W = 6, 7, 8 also 0 (seconds).
Validation of the DFS code itself: see stage 3b.

## Issues found

1. **F1 (doc, must fix before any write-up)**: the E-013 journal says, for the Z side, "even rows: first block=(2,1,0),
   second block=(0,1,2)". Read in CNOT order (the B block comes first for Z checks), that rule has 54 data-qubit collisions.
   The evaluated circuit permutes the **A block** (applied second) as (2,1,0) on even rows; the B block is (0,1,2) on both
   parities. Write the term orders explicitly: Z even [3,4,5,2,1,0], Z odd [3,4,5,0,1,2], X even [0,1,2,5,3,4],
   X odd [2,1,0,5,3,4]. The root cause is that `order_terms(kind, pi, sigma)` takes (A-permutation, B-permutation)
   whatever the time order.
2. **F2 (wording)**: the journal says the theorem would need Corollary 1 (non-interleaved). The lower bound only needs
   Prop. 3, which holds for any single-ancilla SEC; Corollary 1 is the converse direction. Non-interleaving is still true
   and worth stating, but it is not load-bearing for d_circ = 10.
3. **F3 (scope)**: "d_circ = 10" is for the evaluator's memory experiment and fault set (SD6). It does not cover models
   with correlated multi-operation faults, leakage, or a different gate set (e.g. SI1000's CZ compilation, where the
   hook structure changes). Say "under circuit-level noise with independent single-operation faults".
4. **F4 (minor)**: stim `search_for_undetectable_logical_errors` with the evaluator's truncation (size 4, degree 4)
   only reaches 12 on this circuit; on its own it is not a useful certificate for BB108.
5. Novelty: nothing found, but only search-engine level; lit-scout should do a full pass before a claim (stage 4).
