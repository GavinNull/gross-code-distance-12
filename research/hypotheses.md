## H-001 · gross code 存在比 IBM 深度-8 调度更好的 syndrome 提取调度
- **状态**：abandoned（新颖性不足，2026-10-02）
- **放弃原因**：已被先发表。Strikis–Browne–Beverland（arXiv 2603.05481）给出同深度、猜想 d_circ=11 的电路
  （IBM 调度为 ≤10），并证明非交错电路达不到 12，逻辑性能最多提升一个数量级；
  AlphaSyndrome（arXiv 2601.12509，MCTS）也报告超过了 IBM 的 BB 码调度。lead 已在 arXiv 核实两篇摘要。
  另：IBM 原文为 depth-7（7 层 CNOT），“深度-8”是记错。详见 `research/literature/novelty-schedule-search.md`。
- **后续**：方向调整建议待 PI 决定（见 STATE“待人决策”）。gross code baseline（E-002）仍然需要，作为任何后续方向的对照。
- **预测**：在不增加 CNOT 层数的前提下，存在调度使电路级距离保持 12，
  且 SI1000 噪声 p=1e-3 下每轮逻辑错误率显著更低（或同等错误率下层数更少）。
- **可证伪方式**：在约定算力预算内，LLM 进化搜索与模拟退火均找不到更优调度。
- **相关实验**：（无）
- **证据**：（无）

## H-003 · 码 + 电路联合设计能把 gross code 的“比特-错误率”前沿往下推（定稿，2026-10-02）
- **状态**：open（长期目标；2026-10-02 主线改为 H-004，原因见 E-004 与 `research/proposals/2026-10-02-H004-恢复电路距离.md`）
- **背景**：PI 选定“求大”方向。指标依据 `research/literature/codesign-landscape.md`、`resource-metrics.md`
  （OmniQEC 2607.25865 与 IBM 2606.02418 的关键说法已由 lead 在 arXiv 原文核实）。
- **设定（约束）**：校验权重 ≤ 6；Tanner 图 thickness ≤ 2；每个校验一个辅助比特的标准电路（调度可搜）；SD6 噪声；BP-OSD 解码。
- **指标**：
  - **A（比特）** Q = (n + 校验数) / k，BB 码即 2n/k；副指标 Q′ 分母用 k−1（对应 Tour de gross 只有 11/12 个可用逻辑比特）。精确计算，不靠采样。
  - **B（错误率）** 每逻辑比特每轮逻辑错误率，X/Z 联合采样，paper 边界口径。
    搜索阶段只在 p=4e-3 直接采样排序；≤5 个入围码再外推到 p=1e-3（失败谱 ansatz，2511.15177 §3.2 / 2506.03094 A.7），并与 IBM 式拟合并列报告。
  - **判定**：用我们自己的管线测出已知码 × 最好已知电路的 (Q, B)，取下包络线。
    已知码：[[72,12,6]]、[[108,8,10]]、gross [[144,12,12]]、two-gross [[288,12,18]]；电路：IBM、Strikis（E-003），条件允许时加 Shaw–Terhal morphing（2407.16336）。
    新组合的点必须落在包络线下方，且置信区间不跨线，才算改进；改进幅度表示为“同等错误率下比特数之比”。
- **预测**：存在满足约束的码 + 调度组合，在 p=4e-3 下严格位于包络线下方。
- **可证伪方式**：在约定算力预算内找不到包络线下方的点；或改进经 auditor 复核后消失。
- **与竞争工作的差异**：
  - OmniQEC：同样是 LLM 驱动、电路级评估，但调度固定为边着色，比较时不控制每逻辑比特的比特数；
  - IBM 2606.02418：只看码参数，没有电路；
  - Strikis：只优化 gross code 的调度，不搜码。
- **已知局限（结论里必须写明）**：memory 的错误率不等于整机开销。整机还取决于逻辑操作（LPU 等），新码的逻辑操作没有现成方案（resource-metrics.md）。
  “memory 的 B 改善 N 倍”不得写成“整机省 N 倍”。
- **相关实验**：E-003（对照电路）

## H-004 · 存在保距离的 syndrome 提取电路，使 [[90,8,10]] / [[108,8,10]] 的 d_circ 从 8 提升到 10（2026-10-02）
- **状态**：**supported for [[108,8,10]]**（E-013，auditor 复核并证明 d_circ = 10，2026-10-05）；[[90,8,10]] 在可分段电路中不可能（E-005），仍开放于交错 / 不可分段电路
- **设定**：每个校验一个辅助比特、所有校验每轮都测（含冗余行）、sd6 噪声；深度不超过 IBM 原电路（摊销后 8 层）。先考虑非交错电路，必要时扩展到交错 / 流水。
- **预测**：至少一个码存在 d_circ 上界 = 10 的电路（在评估器的四路搜索下找不到 ≤9 的逻辑错误）。
- **可证伪方式**：S1 证明非交错电路的上界 <10，且在约定预算下交错 / 流水搜索也找不到；或者找到的电路经 auditor 复核发现 ≤9 的见证。
- **证据标准**：非交错电路可以用 Strikis Corollary 1（d_circ = d_ext(E)）**精确**计算；其他电路只能报告上界加见证。
- **对照**：IBM 原电路（d_circ ≤8）；穷举 / 退火的项顺序空间；LLM 进化（H-002）。
- **相关实验**：E-005（S1）、E-010（BB108 三色着色：全部 ≤9，严格负面结论）
- **证据（E-005 + auditor 确认，2026-10-03）**：可分段电路下 BB90 ≤ 9、BB108 ≤ 10。
  推论：**BB90 要达到 10，必须用交错电路，或者两两不交错但不可分段的流水电路（IBM 就属于这一类）**；
  BB108 在可分段电路中仍可能达到 10，但需要非均匀调度（均匀调度深度 8 时 ≤ 9）。

## H-005 · BB 码的电路级解码存在大幅提升空间，可由 AI 发现的解码器兑现（2026-10-03，主线，草案）
- **状态**：open（E-006 先量化提升空间，再决定是否投入）
- **动机**：E-003 审计发现，p≈0.005 下 gross code 约 90% 的逻辑失败属于解码器次优（真实故障组合比解码器的解更可能）。
  如果解码器能修好其中大部分，同样的硬件和码，逻辑错误率可能下降接近一个数量级，直接改变资源估计。
- **关键未知**：这个提升空间在更实际的 p（≈1e-3）下还剩多少？解码器失败的最低故障权重是否低于 ⌈d_circ/2⌉（若是，低 p 下存在指数级损失）？
- **竞争**：Google（AlphaQubit）、IBM（Relay-BP 等）、Nvidia 等都在做 qLDPC 解码器；新颖性待 lit-scout 核实。
- **相关实验**：E-006
- **修订（2026-10-03，lit-scout 调研 + lead 核实 2506.01779 与 2604.08358）**：BP-OSD 的大幅提升空间**文献里早已被兑现**。
  Relay-BP（IBM，开源，有 FPGA 实现）在 gross code 上比 BP-OSD 低 10–100 倍；神经网络 / 近最优解码器（Cascade、Tesseract、telescoping）又比现有解码器低约 17 倍（p=1e-3），但达不到超导要求的 1 µs 实时。
  **修订后的目标**：用 AI 发现 FPGA 友好的消息传递类解码启发式，**以 Relay-BP 为基线**，缩小它与近最优之间的差距。
  新颖性：未找到用 LLM / 进化搜索发现电路级解码算法的工作（中等证据）。最强对手：IBM Relay-BP 团队。
- **E-008（2026-10-04）**：在 BB72 / BB90、p=3e-3 下，相对 MLE 的提升空间上限只有约 1.6–2 倍，不足以构成颠覆性改进；空间在大码、低 p。
  H-005 能否成立，取决于 gross 上固定权重失败谱的测量（E-006 方法 b）。
