“找比 IBM 更好的非交错调度”已经很拥挤，而且上限被证明是 11。

## 为什么新方向值得做

- **原文明确留下的开放问题**。2603.05481 v2 §IV.3 原话：
  “It therefore remains an open question whether any interleaved circuit can achieve circuit distance 12.”
- **目标是二值的、可严格验证的**：d_circ = 12，要么做到，要么做不到。正适合“AI 大胆搜、裁判严格判”的范式。
- **有理论抓手**：该文 Theorem 1 说明，从非交错电路出发、只调时间得到的交错电路距离不会下降。
  因此可以从 Strikis 的 d_circ=11 电路出发搜索，起点不会更差。
- **没有找到已做过的工作**（证据强度中等，见下方风险）。

## 建议路线（分两步，第一步本身就有价值）

**第一步 · 公平基准 + 精确验证**（低风险，约 1-2 周）
- 在同一噪声模型、同一解码器下，对比 IBM、Strikis（d_circ=11）两个电路的电路级距离与逻辑错误率。
  lit-scout 没有找到任何人在 gross code 上做过这种同口径比较。
- 搭建**精确的电路级距离验证**（MIP/SAT）。`search_for_undetectable_logical_errors` 只给上界，
  声称 d_circ = 12 必须有下界证明，所以这一步无论如何都要做，它也会成为评估器的一部分。
- 独立验证 Strikis 的 d_circ = 11 猜想。他们只有上界搜索支持；验证成功或失败都是可报告的结果。

**第二步 · 交错电路搜索，目标 d_circ = 12**
- 以 Strikis 电路为起点，在交错 / 跨 cycle 交替电路空间中搜索。
- 搜索器：LLM 进化、模拟退火、随机搜索三者在同评估预算下对比（H-002）。
- 打分：L0 合法 → 电路级距离（先上界，再精确）→ 最小权故障数 → 逻辑错误率。

## 风险（主动说明）

0. **（2026-10-02 补充，lead 自查）实际收益有限**：逻辑错误率主导项约为 p^⌈d/2⌉。
   d_circ 10→11 把指数从 5 提到 6（Strikis 已做到）；11→12 时 ⌈11/2⌉ = ⌈12/2⌉ = 6，**指数不变**，只改善系数。
   因此本方向主要是理论价值（回答开放问题），对实际错误率的改善有限。初版建议书没有指出这一点。

1. **可能做不到**。d_circ = 12 可能本来就不可能，而“没搜到”不等于“不存在”，失败时很难发表。
   缓解：第一步的基准与精确验证本身可以独立成文。
2. **动机被削弱**。Shaw–Terhal（2407.16336）用 morphing 电路得到另一个 [[144,12,12]] 码，d_circ ≤ 12（上界）。
   Strikis 在附录 H 自己说，这降低了做交错电路的动机。我们的回答是：这个问题针对 gross code 本身，
   而 IBM 的架构（2506.03094）就是围绕 gross code 设计的。
3. **新颖性证据中等**。检索依赖搜索引擎，2604.09797 等几篇只读到摘要级内容，“未找到”的覆盖面有限。
4. **待核对**：IBM 原调度本身可能已经是交错的（scout 推断，原文未写明）。
   lead 会在 E-002 完成后写脚本，从电路直接判定，必要时修正本建议。
5. **算力**：精确距离验证（MIP/SAT）在 144 比特 × 多轮的规模上可能很慢，需要先做可行性测试。

## 其他备选

- **D. 换到 magic state cultivation**：影响力最大，但门槛最高，前期投入会大部分作废。
