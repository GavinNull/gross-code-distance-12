## 结论先说

**短实验这一项做完了：Kunlun 的深度（不回绕 7 层 CNOT）在 R = 1 和 R = 2 时也到不了 4。** 和 E-038 的 R ≥ 3 合起来，N7 对**任意轮数**都不可能。两个都是 42 个 cube 全部 UNSAT、drat-trim 全部 s VERIFIED。

**一般流水 P = 8、9 仍然未决**，但我把它拆清楚了，并证明了三个比 E-038 的 V 类大得多的子类不可能：

| 类 | 结论 | 证书 |
|---|---|---|
| N7，R = 1（恰好一轮的 memory 实验） | **不可能** | 42/42 cube DRAT 验证 |
| N7，R = 2 | **不可能** | 42/42 cube DRAT 验证 |
| U_X(8)：W8 中所有 X 校验同一复位层，Z 校验各自任意 | **不可能**（体内） | 1 个 CNF，DRAT 验证 |
| U_Z(8)：W8 中所有 Z 校验同一复位层，X 校验各自任意 | **不可能**（体内） | 8 个 CNF（Z 层相对 X0 的 8 种），DRAT 验证 |
| Mg7 的 U_X、U_Z（测量与复位合并一层、周期 7） | **不可能**（体内） | 1 + 7 个 CNF，DRAT 验证 |
| W9 的 U_Z，且 Z 层与 X0 的复位层相差 δ ∈ {2,…,7}（mod 9） | **不可能**（体内） | 6 个 CNF，DRAT 验证 |
| W8、W9、Mg7、Mg8 一般情形 | **未决** | — |
| W9 的 U_X；W9 的 U_Z 且 δ ∈ {0, 1, 8} | **未决**；U_X 与 δ = 1 里存在没有任何 HH/HHM/DDH 见证的调度（只剩 DHH、HHH 型权重 3） | — |
| 任何一类里 d_circ = 4 的调度 | **没有找到** | — |

前三个子类的不可能性只用了 W8 里最简单的一种见证：**一个辅助比特钩子（散布到该校验最后两个 CNOT 的比特）+ 两个数据错误**（DDH2）。W9 与 W8 的表现完全不同：在 W9 里这三种静态类型挡不住 U_X，剩下的障碍全是 DHH、HHH，这是 W9 可能有解的唯一迹象，但我没找到解。

## 类的精确定义

约定与 E-038 相同：一轮 P 层，每层每个比特至多一个操作；校验 k 的辅助比特在第 π_k 层复位，6 个 CNOT 在其后互不相同的层，第 μ_k 层测量，下一实例在 π_k + P 层复位；每轮同一调度（实例 j = 实例 0 平移 jP）；同一数据比特上（来自 14 个校验的）CNOT 模 P 互不相同；确定性奇偶条件同 E-038。14 个被测校验、84 个 Tanner 耦合器、每校验一个辅助比特、无旗标。

- **W(P)**（复位与测量各占一层）：μ_k − π_k ≤ P − 1，所以每个校验 6 个 CNOT 的时间跨度 ≤ P − 3。P = 8：6 个 CNOT 恰好占满 6 个连续层，辅助比特 8 层全忙；P = 9：6 个 CNOT 在 7 个连续层里。π_k 每个校验自由。
- **Mg(P)**（测量与下一次复位合并为一层；单独的一类，不在 W 里）：μ_k − π_k ≤ P，跨度 ≤ P − 2。Mg7：6 个 CNOT 占满 6 个连续层，第 7 层是测量+复位，周期 7。
- **U_X(P)** = W(P) 中所有 X 校验的 π 相同（Z 校验的 π 各自任意）；**U_Z(P)** 同理。E-038 的 V(P, δ) = U_X ∩ U_Z。由全局时间平移，U_X 就是"X0 与所有 X 在第 0 层"，U_Z 拆成"所有 Z 在第 δ 层"，δ = 0..P−1。
- **N7(R)**：E-038 的不回绕 7 层类（全部第 0 层复位、CNOT 在 1..7、第 8 层测量），恰好 R 轮的 memory 实验（评估器模板：数据复位、R 轮、数据读出；探测器只用 14 个被测校验），两个基底。

SD6 下体内故障模型只依赖 CNOT 时间：第一个 CNOT 之前的辅助比特错误平凡，最后一个之后的等于测量翻转，复位翻转等于上一实例的测量翻转。所以 W(P) 与 Mg(P) 只差窗口约束，Mg 用的合并 MR 层不引入新的故障机制。

"体内"不可能的意思与 E-038 的 V 类相同：轮数足够多时，类里每个电路都有权重 ≤ 3 的不可检测逻辑（至少一个基底），复位与不复位辅助比特都一样。

对称性：9 个平移里除恒等外没有一个保持被测校验集合（重新算过）；保持它的数据比特置换有 2 个保持类型、2 个交换 X/Z（`e038/autos.py`）。这次没有用对称性剪枝，因为限制我的不是 2 倍或 4 倍。

## 我怎么想的

### 1. E-038 的全局 CEGAR 为什么卡住

我先读日志：108 轮、9,000 多个模式之后，SAT 模型仍然带权重 2 的 HH 见证，每轮只新增 1–3 个模式，每次 SAT 调用 400–900 s。CEGAR 在慢慢"发现"一个本可以一次写完的子句集。

所以第一步是**静态完整枚举**。见证的残余（D、H 槽数据集合之异或）必须与全部被测读者对易、观测量非零；用 2^18 张表筛，每个基底满足的槽型多重集只有：HH 556、HHM 556×7、DDH 420（其中钩子 |U| = 2 的 210 个）、DHH 8,376、HHH 70,596；D、H、DD、DH、DDD、DDM、DMM、DHM、HMM 一个也没有。轮次：最小权重见证在"共享探测器"图上必然连通（否则每个分量各自相消，观测量非零的那个分量是更小的见证）；W(P) 与 Mg(P) 里每个槽只影响 r−1..r+2 轮，所以相邻槽轮差 ≤ 3，连通的 3 槽见证排序后相邻轮差都 ≤ 3。在这个范围内枚举全部轮次向量得到 HH、HHM、DDH 的完整模式集（每基底 318,668 个，非平凡子句约 10 万）。

完整性与正确性实测（`validate_static.py`）：W8 15 个、W9 10 个、Mg7 5 个随机合法调度的全部最小权重见证中，属于这三类的 11,373 个模式**全部**在静态集合里；5,828 个正例与 8,500 个负例上，我的子句是否被违反与审计者独立语义 `gpat.GSem.cancels` **逐个一致**；351 个相消实例在无噪声 stim 周期电路中物理注入后全部 0 个探测器、观测量翻转。

加上静态子句后 W8 里没有权重 2 的调度 0.1 s 就能找到，权重 2 的问题消失。但全局问题仍然很难，下面几个观察决定了后面的路线。

### 2. 难点在哪里：复位层的组合，而不是见证

- **固定全部 14 个复位层时问题很容易。** W8 随机抽的 26 个完整复位层向量（及 V8 δ = 3）只用 HH/HHM/DDH 子句就 UNSAT，每个 0.1–30 s；W9 的 3 个也 UNSAT。甚至只用 DDH2 就够。
- **放开复位层，代价指数增长。** 固定 10 个 20–80 s，固定 7 个 540–1,100 s，固定全部 X、放开全部 Z 660 s；UNSAT 核心（失败假设）一般含 7–13 个复位层，不小。按复位层切 cube 要 8^13 ≈ 5×10^11 个，不可行。
- **没有局部引理。** 只用一个基底的子句（全部 7 个散布者）W8 是 SAT；只取 1–4 个散布者的子系统也全是 SAT。两个基底、全部校验同时起作用。
- **类型同步的子类很快。** 这就是上表里能做完的部分：U_X(8) 一次求解 206–246 s，U_Z(8) 每个 δ 0.4–173 s。

全局实例我交给 CaDiCaL 3.0.1 长时间跑：W8 + HH/HHM/DDH 1.9 h、W8 + 全部 DDH 5.1 h、W9 + DDH 0.5 h，都没有结束，按预算停掉。W8 只用 DDH2 时全局是 SAT（373 s），模型里有 144 个 |U| = 4 的 DDH 见证，所以 DDH2 只在同步子类上够用。

### 3. W9 为什么不一样，以及搜索

W9 的 U_X 在 HH/HHM/DDH 下是 **SAT**（1,415 s），U_Z 在 δ = 1 也是 SAT（112 s），而 δ = 2..7 是 UNSAT。SAT 模型里所有 X 在第 0 层、大多数 Z 在第 0 层、个别 Z 移到第 1 或第 8（= −1）层，也就是"接近不回绕 N7、只把少数校验错开一层"；它们只剩 43–65 个 DHH、HHH 型权重 3 见证。这说明在 Kunlun 的周期（9 层）上，DDH 这类最简单的障碍可以靠流水绕开，剩下的问题是更复杂的三错误组合。

我用两种启发式找 d_circ = 4：(a) 模拟退火（交换校验内两个 CNOT、把一个 CNOT 移到窗口内空层、整校验平移一层，非法即拒绝；分数 = 权重 ≤ 3 见证数），两条链各 12 分钟，最好到 12 个权重 3 见证后停滞；(b) 固定复位层后在子类内跑 CEGAR，每次 SAT 调用 15 分钟以上，太慢停掉；大邻域搜索（固定除 2–4 个校验外的全部 CNOT 求解）同样被单次求解拖慢。**没有找到。** 这些启发式不构成任何不可能性的证据。

### 4. N7 的 R = 1、2：做完了

有限 R 的故障模型（`finite.py`）就是体内模型加上边界：数据切口、钩子、测量翻转三类，读者在第 R 个实例之后看到的错误记到最终读出探测器 D(c, R)，数据复位翻转是第 0 轮最早读者之前的切口，读出翻转是 r = R 的切口。它与 stim DEM 机制集合逐个相等（180 组：随机 N7 调度 × R = 1、2、3 × 两个基底），与评估器模板的最小权重处处一致（`validate_finite.py`）；有限模式子句与机制表在 928 个正例、4,000 个负例上逐个一致（`validate_finite_clauses.py`）。

R = 1、2 时轮次是绝对的，所以可以把**全部**类型的全部模式静态写进 CNF：R = 1 用 HH、HHM、DDH、DHH、HHH 全部（14.2 万变量、81.6 万子句，sha256 98bd8585…），R = 2 只用 HH、HHM、DDH、DHH（6.7 万变量、65 万子句，sha256 c15b5096…；UNSAT 只需要每条子句可靠，不需要类型完整，去掉 HHH 让 CNF 小了三倍）。整体求解一个半小时没结束，于是按 X0 两个 CNOT 的层号切成 7·6 = 42 个 cube（合法性迫使它们层号不同，所以恰好覆盖），每个 cube 用 CaDiCaL 3.0.1 出 DRAT、drat-trim 检查：

| | cube | 求解 | drat-trim | 最大证明 | 结果 |
|---|---|---|---|---|---|
| R = 1 | 42 | 5.7 CPU h（单个 ≤ 844 s） | 2.7 CPU h | 463 MB | 42/42 UNSAT、s VERIFIED |
| R = 2 | 42 | 4.1 CPU h（单个 ≤ 672 s） | 2.1 CPU h | 473 MB | 42/42 UNSAT、s VERIFIED |

`cover.py` 核对了：42 个 cube 恰好是全部有序对 (a, b)，a ≠ b；每个 cube 的 CNF 逐字节等于基础 CNF 加它的单元子句；每个 cube 都有 sha256 对得上的 UNSAT + VERIFIED 记录。

和 E-038 的 R ≥ 3 合起来：**每个 N7 电路、每个 R ≥ 1，至少一个基底有权重 ≤ 3 的不可检测逻辑。** 有限模型用的是复位辅助比特（评估器模板）；R = 1 时复位与否无区别，R = 2 时按 E-038 审计 3.1 第 5 点，复位模型的每个见证也是不复位电路的见证，所以结论对不复位同样成立。

## 局限

- 一般 W8、W9、Mg7、Mg8 没有定论。W8 的证据（所有抽到的完整复位层向量都在秒级被否定、两个同步子类不可能）倾向于不可能，但这不是证明。
- 体内结论的可靠性靠：E-038 已审计的模式语义、这次 8,500 个负例 + 5,828 个正例与审计者独立语义逐个一致、351 个 stim 物理注入、11,373 个见证的静态完整性抽检。W 类合法性 CNF 的完备性沿用 E-038 的抽检（含 W8、W9 随机调度）；Mg 类的合法性只差窗口一个常数，我没有单独做完备性抽检。
- R = 1、2 的结论依赖有限模型 = stim DEM（180 组机制集合相等）与评估器模板的探测器约定（只有 14 个被测校验的探测器）。如果实验把 4 个未测校验的数据奇偶也当探测器，R = 1、2 的结论需要重算。
- 启发式搜索时间很短（退火两条链各约 12 分钟），"没找到"几乎不带信息。

## CPU 与过程

约 60 CPU h（预算 80）：R = 1、2 的 84 个 cube 与 DRAT 14.6；全局 CaDiCaL 尝试（W8、W9、Mg7 各种子句集）约 13；pysat 版本的有限 R 整体求解与有限 CEGAR 约 14；W8 的各种偏移固定标定约 5；子类 CEGAR 与启发式约 6；同步子类 DRAT 1.1；验证与其他约 6。同时工作进程一般 7–8 个。

过程失误，如实记下：
1. 有两次在 zsh 里写 `set -- $job` 与 `$L` 时没有分词（zsh 默认不拆），第一次产生了带空格的空文件名（已删），第二次让 R = 1 的 cube 工作进程启动即失败、空转约 30 分钟才发现；改用 `${=L}`。
2. 两次短暂超过 8 个工作进程（9 个，各一两分钟，发现后按 PID 停掉一个）。
3. 有两次在 shell 里误用了系统 `python3`（一次空 heredoc、一次 `print(1)`），没有运行项目代码，之后全部用 `uv run`。
4. 标定脚本里一次在建立 cube 字面量（会新建辅助变量与子句）之后没有把新子句同步给求解器，几次"cube 很慢"的计时其实是在解全局问题，发现后重做；日志里的标定数字都是修正后的。
5. W9 U_Z δ = 0、8 和若干全局求解是我按预算停掉的，记为未完成，不是 SAT 或 UNSAT。
6. 为加速 R = 1、2 开了从尾部倒序处理的额外工作进程，两头相遇时我按 PID 停掉多余的进程，被停掉的 cube 由另一端重做；所有 cube 都有完整记录（`cover.py`）。

只删了我自己生成的临时文件（未完成的证明、cube CNF、scratchpad 里的标定脚本）。
