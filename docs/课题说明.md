## 1. 背景与动机

### 1.1 为什么纠错开销是关键瓶颈

容错量子计算的物理比特数 ≈ 逻辑比特数 × 每个逻辑比特的编码开销 + magic state 工厂开销 + 路由开销。真正决定“能不能做出有用量子计算机”的，往往是后面这几项开销，而不是逻辑算法本身。

以 RSA-2048 为标志性 benchmark：

| 年份 | 工作 | 物理比特估计 | 主要改进来源 |
|---|---|---|---|
| 2019/2021 | Gidney & Ekerå | ~2000 万 | 表面码 + lattice surgery + 算法优化 |
| 2025 | Gidney, *How to factor 2048 bit RSA integers with less than a million noisy qubits* | < 100 万 | 近似算术、yoked surface code、magic state cultivation |

几年内下降了约 20 倍，几乎全部来自 **纠错/容错层面的工程与理论改进**，而非新硬件。这说明这一层“还有很多油水”，而且每次改进都有直接、可量化的影响。

### 1.2 为什么适合 AI 来做

这个方向有一个难得的特性：**评估器又快又准**。

- `stim` 可以在几秒内对上千比特的 Clifford 电路采样百万次；
- 码的参数 `[[n, k, d]]`、电路深度、逻辑错误率都是客观数值；
- 不需要人判断“好不好”。

这正是 FunSearch / AlphaEvolve 类方法成功的前提：*生成器（LLM 或 RL）大胆提方案 → 自动评估器严格打分 → 进化选择*。AlphaEvolve 已在矩阵乘法、组合数学等“有精确评估器”的问题上拿到 SOTA，而量子纠错是这类问题里影响力最大的之一。

## 2. 核心范式

```
┌──────────────┐   候选程序/方案   ┌──────────────────────┐
│  生成器        │ ───────────────▶ │  评估器（分层）          │
│  · LLM 改写程序 │                  │  L0 合法性校验（毫秒）    │
│  · RL 策略     │ ◀─────────────── │  L1 廉价代理指标（秒）    │
│  · 随机变异     │   分数 + 诊断信息   │  L2 电路级蒙特卡洛（分钟） │
└──────────────┘                  └──────────────────────┘
        ▲                                   │
        └────────── 程序数据库（岛模型） ◀────┘
```

关键设计原则：

1. **搜程序，不搜对象**：让 LLM 写“生成码/调度的 Python 函数”，而不是直接输出一个矩阵。程序更紧凑、可泛化到不同距离，也更可解释（FunSearch 的核心经验）。
2. **分层评估**：99% 的候选在 L0/L1 就被淘汰，只有精英才进 L2 的昂贵模拟。
3. **防作弊**：搜索一定会利用评估器漏洞（例如造出 detector 不确定的电路、或把逻辑算符放到不被测量的地方）。L0 必须足够严格，见 §5.2。

## 3. 四个子方向

### 3.A qLDPC 码搜索

**问题**：在给定结构族里找参数 `[[n, k, d]]` 更好、且在电路噪声下性能更好的码。

- **搜索空间**：
  - Bivariate Bicycle (BB) 码：由两个多项式 `A(x,y)`, `B(x,y)` 和环大小 `(l, m)` 决定（IBM 的 [[144,12,12]] “gross code” 就是一例）；
  - 推广：two-block group algebra (2BGA) 码、lifted product 码、hypergraph product 码；
  - 约束：权重 ≤ 6（硬件友好）、Tanner 图 thickness ≤ 2（可两层布线）。
- **指标**：`k·d²/n`（编码率与距离的综合）、电路级逻辑错误率/每轮每逻辑比特、伪阈值。
- **难点**：精确计算距离 `d` 是 NP-hard。实际用：小码 ILP/穷举，中等码用随机信息集译码给出上界，电路级距离用 `stim` 的 `search_for_undetectable_logical_errors`。
- **可行性**：★★★★☆，有成熟 baseline（IBM 表格、Lin–Pryadko、coprime BB 码等），容易比较。

### 3.B Syndrome 提取电路调度（★ 推荐首选切入点）

**问题**：给定一个码，设计测量 stabilizer 的电路（CNOT 顺序、辅助比特分配、是否用 flag 比特等），使电路级有效距离不降、深度最小、逻辑错误率最低。

- **为什么推荐**：
  - 码固定，搜索空间清晰（本质是 CNOT 的排列/着色问题）；
  - 评估完全自动：`stim` 生成电路 → 检查 detector 确定性 → 算电路级距离 → `sinter` + BP-OSD 估逻辑错误率；
  - 有明确 baseline：IBM gross code 论文给出的深度-8 调度、表面码标准 N/Z 型调度；
  - “hook error”导致电路距离下降是公认难题，坏调度会让距离从 12 掉到 10 甚至更低，提升空间真实存在。
- **搜索空间**：每个 stabilizer 的 CNOT 顺序 × 时间步分配；可选 flag 比特、辅助比特复用、测量轮间交错。
- **指标**：(1) 电路级距离 `d_circ`（硬约束 = 码距离），(2) 每轮 CNOT 层数，(3) SI1000 噪声下 p=1e-3 的逻辑错误率。
- **可行性**：★★★★★

### 3.C Magic state 蒸馏 / cultivation

**问题**：以更少的空间-时间体积制备高保真 `|T⟩` 态。

- 背景：Gidney–Shutty–Jones 2024 的 *magic state cultivation* 把 T 态成本降到接近一个 CNOT 门的量级，是 2025 年 RSA 估计能大幅下降的关键之一。
- **搜索对象**：cultivation 的 check 序列和 post-selection 规则、扩张（grafting）到大码的方式、小型蒸馏协议（triorthogonal 矩阵搜索）。
- **难点**：涉及非 Clifford 门，`stim` 不能直接模拟，需要 Clifford 近似技巧（如用 `H_XY` 替身）或小规模态矢量模拟；评估更贵、更容易出错。
- **可行性**：★★★☆☆，影响力最大，但门槛最高，建议第二阶段再做。

### 3.D Lattice surgery 布局 / 编译

**问题**：给定逻辑电路，在二维芯片上布置逻辑块、路由通道和 magic state 工厂，使总空间-时间体积最小。

- 本质是组合优化（布局 + 调度），RL 和 LLM 进化都适用。
- **指标**：总时空体积（d³ 单元数）、关键路径长度。
- **难点**：评估依赖资源估计模型而非真实模拟，“改进”的含金量取决于模型是否被社区认可。
- **可行性**：★★★☆☆

## 4. 推荐路线

| 阶段 | 内容 | 目标 | 预计时长 |
|---|---|---|---|
| P0 | 复现 baseline | 表面码 & gross code 的标准调度，跑出与文献一致的逻辑错误率曲线 | 1–2 周 |
| P1 | 搭建评估器 | L0/L1/L2 三层评估 + 防作弊校验 + 结果缓存 | 1–2 周 |
| P2 | **3.B 调度搜索** | 先随机搜索 / 模拟退火作对照，再上 LLM 进化 | 3–4 周 |
| P3 | **3.A 码搜索** | 在 BB/2BGA 族里搜多项式，联合优化码 + 调度 | 4–6 周 |
| P4 | 3.C 或 3.D | 视 P2/P3 结果决定 | 开放 |

**为什么先有“傻瓜对照”**：如果模拟退火也能达到同样结果，那 LLM 并没有带来价值。论文必须回答“AI 相对经典启发式搜索的增量在哪里”。

## 5. 方法细节

### 5.1 噪声模型

至少报告两种，便于和文献对比：

- **均匀电路级去极化**（`p` 扫 1e-4 ~ 5e-3）：最常用；
- **SI1000**（超导启发，Gidney 等人使用）：测量/复位噪声更重，更接近真实硬件。

### 5.2 L0 合法性校验（防作弊清单）

候选电路必须全部通过才能打分：

- [ ] 无噪声下所有 detector 确定（`circuit.detector_error_model()` 不报错）；
- [ ] 无噪声下所有 observable 确定、且确实对应码的逻辑算符；
- [ ] 每个 stabilizer 都被测量（检查 detector 覆盖）；
- [ ] 使用的比特数、连接性不超过硬件约束；
- [ ] 电路级距离 ≥ 设定下限（`search_for_undetectable_logical_errors`）；
- [ ] 评估时随机种子由评估器控制，候选程序不能读写文件/网络。

### 5.3 L1 廉价代理

- 电路深度、CNOT 数；
- 电路级距离及最低权重逻辑错误的数量（低权重“坏路径”越少越好）；
- 小 shot 数（~1e4）的逻辑错误率粗估。

### 5.4 L2 精确评估

- `sinter` 多核采样，解码器：表面码用 `pymatching`，qLDPC 用 BP-OSD（`stimbposd` / `ldpc`），可选 `beliefmatching`；
- 报告每轮每逻辑比特错误率及置信区间；
- 收集到 ≥100 次逻辑错误或达到 shot 上限再停止。

### 5.5 LLM 进化搜索设置

- 程序模板：`def schedule(code) -> list[list[tuple[int,int]]]` 或 `def make_code(l, m) -> (A_terms, B_terms)`；
- Prompt 包含：当前最优的 2–3 个程序 + 分数 + 评估器给出的诊断（例如“第 3 层 hook error 导致距离降为 10”）；
- 模型分工：便宜模型做大批量变异，强模型做少量“重构式”改写；
- 岛模型 + 定期迁移，防止早熟收敛；
- 全程记录每次调用的 prompt、程序、分数，保证可复现。

### 5.6 RL 设置（对照或补充）

- 调度问题可写成序列决策：每步选一个 (stabilizer, data qubit) 对放进当前时间层；
- 奖励：稀疏（完成后的电路距离与错误率），需要用 L1 代理做 shaping；
- 环境用 `gymnasium` 封装，策略网络用 `torch`（本机 MPS 可用）。

## 6. 算力评估（本机：M 系列 10 核 / 24GB）

| 任务 | 本机是否够用 |
|---|---|
| L0/L1 评估、LLM 进化循环 | 够 |
| 表面码 d≤11、gross code [[144,12,12]] 的 L2 评估 | 够，但 p≤1e-3 时 BP-OSD 较慢，需要几十分钟到数小时 |
| 大规模扫参、更大的码（n>500） | 建议租云端多核 CPU（BP-OSD 吃 CPU，不需要 GPU） |
| LLM 调用 | 走 API，成本主要在 token，需设预算上限 |

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| 搜到的“改进”是评估器漏洞 | §5.2 严格校验；最终结果用独立脚本重新验证 |
| 改进只在单一噪声点成立 | 必须扫 `p` 并报告多种噪声模型 |
| 解码器差异掩盖调度差异 | baseline 与候选用同一解码器同一参数 |
| LLM 搜索不比经典启发式强 | 预先设置随机搜索 / 退火 / 遗传算法对照 |
| 结果已被他人发表 | 开工前与每阶段结束时做文献检索（arXiv quant-ph） |
| API 成本失控 | 每次运行设 token 预算，缓存已评估程序的哈希 |

## 8. 成功标准

- **最低目标**：在固定码（如 gross code）上找到一个调度，在同等深度下逻辑错误率显著低于公开 baseline，或在同等错误率下深度更低；
- **理想目标**：发现新的 qLDPC 码（或码 + 调度组合），在权重 ≤6、thickness ≤2 的约束下，`k·d²/n` 或电路级性能超过已知最好结果；
- **产出**：开源评估器 + 搜索框架 + 一篇 arXiv 论文。
